# Neoffice fork markers

Everything in this repository that is **ours** and not upstream's carries a
`//// Neoffice` comment saying *why*. At the next upstream merge,
`grep -rn "////"` gives the complete map of our divergence — that is the only
way to tell our intent from theirs and to avoid losing a fix in silence.

This file holds what a comment cannot reach: files with no comment syntax
(JSON, PO, binaries), build artifacts, and the handful of hunks that sit inside
a construct where no comment is legal.

Tooling: `scripts/fork_markers.py` in **bvisible/neoffice-ci** (public), driven
by `.github/workflows/fork-markers.yml`.

### The repo-wide Python 3.12 graft — read this before re-merging

`573ca1486a` prepends `from __future__ import annotations` to **576 modules**,
each now marked with a two-line `#////` comment.

* **Why**: upstream targets Python 3.14 (`requires-python = ">=3.14,<3.15"`,
  `target-version = "py314"`), where PEP 649 makes annotations lazy. The fleet
  runs Frappe v15 on **Python 3.12**, which evaluates them eagerly, so a
  signature such as `"CoreService" | None` raises `TypeError` at import.
* **Generated by** `neoffice-devops/scripts/suite_py312_graft.py` —
  idempotent, re-run after each upstream re-sync.
* **Verified** (2026-09-04): all 576 files compile on CPython 3.12.7 and carry
  `CO_FUTURE_ANNOTATIONS` in the compiled code object — the import is effective
  in every one of them, none swallowed by a docstring.
* **Removal condition**: the whole graft (and `requires-python = ">=3.12"` in
  `pyproject.toml`) goes away the day the fleet moves to 3.14. It is a one-line
  block at the top of each file: at a merge, take upstream's file and re-run the
  script.
* **Merge cost**: 69 of the 86 files touched on both sides diverge *only* by
  this graft — trivial resolutions.

#### `frontend/neoffice-calendar-i18n.ts`
Ours. frappe-ui's experimental calendar writes English by hand; the plugin rewrites its files as Vite loads them

#### `frontend/neoffice-i18n.ts`, `neoffice-i18n-core.mjs`, `scripts/gen-i18n-registry*.mjs`, `src/neoffice/i18nRegistry.ts`
Ours (neoffice-maintenance#1592, 15.10.2026). Upstream wrote Sheets, Slides, Writer and half of the Drive's pages in
English with no `__()`. Rather than a marker and a conflict on each of a thousand lines, the Vite plugin reads those
files as the build loads them (text nodes, `label`/`title`/`placeholder`… attributes, the `label`/`title`/`description`/
`message`… values of objects — made getters in a script, so a list built at load time still reads the language —,
the first argument of a toast, template literals as `__('… {0}', [x])`) and rewrites them through `__()`. The
files stay upstream's byte for byte. Three things keep it honest:
* `src/neoffice/i18nRegistry.ts` (GENERATED) lists every message, so the extractor of the catalogues finds them;
* `src/test/neoffice-i18n.test.ts` fails when that list is stale, and when a rewrite would not parse;
* `KEEP` (data the code compares with or stores) and `OVERRIDES` (sentences a template breaks around an element)
  in `neoffice-i18n-core.mjs`: each says why. A literal comparison with a message found, for every one of them, by
  looking: `label`s that were also action names, the default label of a Writer tab.
frappe-ui's editor (Writer's toolbar, slash menu, table, link and media tools; Mail's composer shows the same module) is
English only as well: the files of `node_modules/frappe-ui/src/molecules/editor/` listed in `FRAPPE_UI_EDITOR_FILES`
are read the same way (a file not in the list is not read, and one of a later release is said only once somebody has
looked at it). A command's label is read when it is shown (`menu.ts` builds them when the module loads, before the
translations), so two `OVERRIDES` make `command()` and `tableCommand()` lazy. The rest of frappe-ui (its components:
pickers, dialogs, list footers) is not read: a decision of its own.
At a merge: `node scripts/gen-i18n-registry.mjs`, translate what is new (the `translate` skill, Haiku), run the
test. An override whose text moved from upstream fails the build with its file: say the sentence again (the same at
a bump of the frappe-ui commit in `package.json`).
