# Neoffice fork markers

Everything in this repository that is **ours** and not upstream's carries a
`//// Neoffice` comment saying *why*. At the next upstream merge,
`grep -rn "////"` gives the complete map of our divergence — that is the only
way to tell our intent from theirs and to avoid losing a fix in silence.

This file holds what a comment cannot reach: files with no comment syntax
(JSON, PO, binaries), build artifacts, and the handful of hunks that sit inside
a construct where no comment is legal.

Tooling: `scripts/fork_markers.py` in **bvisible/neoffice-ci** (public), driven
by `.github/workflows/fork-markers.yml`.

### The repo-wide Python 3.12 graft — read this before re-merging

`573ca1486a` prepends `from __future__ import annotations` to **576 modules**,
each now marked with a two-line `#////` comment.

* **Why**: upstream targets Python 3.14 (`requires-python = ">=3.14,<3.15"`,
  `target-version = "py314"`), where PEP 649 makes annotations lazy. The fleet
  runs Frappe v15 on **Python 3.12**, which evaluates them eagerly, so a
  signature such as `"CoreService" | None` raises `TypeError` at import.
* **Generated by** `neoffice-devops/scripts/suite/py312-futurize.py` —
  idempotent, re-run after each upstream re-sync.
* **Verified** (2026-09-04): all 576 files compile on CPython 3.12.7 and carry
  `CO_FUTURE_ANNOTATIONS` in the compiled code object — the import is effective
  in every one of them, none swallowed by a docstring.
* **Removal condition**: the whole graft (and `requires-python = ">=3.12"` in
  `pyproject.toml`) goes away the day the fleet moves to 3.14. It is a one-line
  block at the top of each file: at a merge, take upstream's file and re-run the
  script.
* **Merge cost**: 69 of the 86 files touched on both sides diverge *only* by
  this graft — trivial resolutions.

### Files that cannot carry a comment

`fork_markers.py check` accepts these only because their **full path** is named
here.

#### `suite/drive/doctype/wopi_settings/wopi_settings.json`
**Entirely ours — a new Single DocType, no upstream equivalent.** Configuration
of the on-prem Collabora Online (WOPI) backend used instead of shipping customer
documents to `view.officeapps.live.com`. Ported from the standalone Neoffice
`drive_wopi` app (`f20a6f284`). Module `Drive`, `issingle: 1`, permissions:
`System Manager` (read/write/create) only. Fields, all ours:

| Field | Type | Purpose |
|---|---|---|
| `enabled` | Check | master switch; off = fall back to upstream's viewer |
| `section_collabora` | Section Break | — |
| `collabora_server_url` | Data | empty = same host, proxied by nginx |
| `column_break_1` | Column Break | — |
| `jwt_secret` | Password | signs the WOPI callback tokens (see `wopi/token.py`) |
| `jwt_expiry_hours` | Int | token TTL, default 10 |
| `section_status` | Section Break | — |
| `connection_status` | Data | last probe result |
| `last_check` | Datetime | last probe timestamp |

At a merge: keep the file whole. Nothing upstream collides with it.

#### `suite/fixtures/role.json`
Ours, one field on one row (`e20b2ac06 fix(security): frontend signups must stay
Website Users`):

| Row | Field | Upstream | Ours | Why |
|---|---|---|---|---|
| `Suite User` | `desk_access` | `1` | **`0`** | A Suite portal account must not be able to reach `/app`. With `desk_access: 1` a self-service signup became a desk user: it lands on the desk after login (a dead end for someone with no desk role) and it counts against the instance's user quota. |
| `Suite User` | `modified` | `2026-07-21` | `2026-08-31` | fixture bump so the change re-imports |

**This one WILL come back at every merge** — it is a fixture upstream owns and
keeps at `1`. Re-apply `desk_access: 0` after each merge, and re-test the
Website-User pass (`CLAUDE.md` rule 1b).

Ours (`2c44b2064 fix(build): rendre le build reproductible hors de mon poste`),

#### `suite/templates/files/blank.docx` · `blank.xlsx` · `blank.pptx`

blank Word / Excel / PowerPoint file from the launcher or the Drive Create menu.
No upstream equivalent — upstream has no Office editing. Not generated: do not
try to rebuild them.

`bench build --app suite` on an instance only rebuilds the desk bundles

Sonnet pass does this automatically on the next push).

### Hunks no comment can reach

Three hunks sit **inside a multi-line Vue opening tag, between attributes**,
where neither an HTML comment nor a JS comment is legal. In each case the
**enclosing element carries the marker** directly above its opening tag.

| Location | Change | Where the reason lives |
|---|---|---|
| `frontend/src/apps/calendar/pages/CalendarView.vue` — `@update:visible-calendars`, `@reload` on `<NeoCockpitSidebar>` | the handler now **persists** the show/hide choice (`toggleCalendarVisibility` → `set_calendar_visibility`) instead of splicing a local array; `@reload` lets the settings dialog refresh the list | 7-line `<!-- //// -->` block above `<NeoCockpitSidebar` |
| `frontend/src/shell/LauncherView.vue` — `:to` / `:href` on `<LauncherTile>` | a tile with `external` leaves the SPA (plain `<a>`, Mail → `/app/webmail`) | 6-line `<!-- //// -->` block above `<LauncherTile` |
| `frontend/src/shell/LauncherView.vue` — `:label` / `@click` on `<LauncherTile>` | a tile with `createsOffice` creates a blank Office file in Drive and opens it in Collabora; the label shows “Creating…” meanwhile | same block |

Whitespace-only divergence: `frontend/src/shell/LauncherView.vue` re-indents the
launcher body by one level (the page is now split into the cockpit rail and a
content column). **Take our side there**; everything else in that file is
substantive.
